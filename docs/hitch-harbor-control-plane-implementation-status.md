the repository contains both an implementation and a test that exercises the
specified behavior. `npm run check` is necessary but does not by itself prove
that a missing requirement exists.

## Required test gaps

- GitHub-hosted Ubuntu/Windows × Node 22/24 packaged-harness canary results are
  pending until this branch is pushed; the same cache/integrity canary passes
  locally on Darwin arm64.
- Remote-worker duplicate/conflicting event delivery, stale generation/epoch,
  digest mismatch, path traversal and forged execution-lease evidence are
  rejected; terminal-uncollected restart recovery, never-started requeue,
  accepted-worker reconnect and packaged-runner no-replay are covered. Remote
  capture transport additionally rejects identity/completeness mismatch and
  missing, non-canonical, symlinked or hard-linked payload evidence before it
  can become a valid promoted run.
- Capture redaction for standard headers, custom secret headers and known
  credential values is covered. Local Harbor host logs, bridge credential-name
  handoff, provider capture and complete run/eval evidence trees are also
  secret-scanned; the remote short-TTL envelope and separate controller/worker
  root scan are covered. BuildKit handle resolution, rotation/cache identity,
  value-free argv/state, failure redaction, and real-Docker
  image-layer/exported-cache scans are covered.
- Fixed-machine admission, hard-limit, OOM, ledger-leak and fenced-cleanup
  acceptance is covered both by the raw Docker crash canary and by one full
  managed-Harbor 20-trial report combining image single-build/cache evidence,
  bundle verification and invalid-reward aggregation assertions.
- GPU admission and Compose merge are tested without hardware; a GPU-host
  execution canary must still prove the device is usable inside Candidate and
  separate-Verifier environments.
